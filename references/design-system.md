# デザイン仕様（KPIスライド）

導入第1社向けに作った1枚KPIスライドの見た目を、他社・他月でも再現するための仕様。
`scripts/build_deck.js` はこの仕様を実装済みなので、通常はこのファイルを直接読まなくても
`build_deck.js` に data.json を渡せば同じ見た目になる。デザインを変える相談を受けたときや、
build_deck.js を拡張するときの参照用。

## スライドサイズ

16:9ワイド（13.333in × 7.5in）。A4縦・A4横で欲しいと言われた場合は、まず理由を確認する
（このスキルは「他社資料と一緒に差し込む」前提でPowerPointワイド画面を既定にしている）。

## カラーパレット

寒色系（ブルー×オレンジ基調）。2026-07-28にユーザー要望で寒色系（スティールブルー）→暖色系
（クレイ）に変更したが、2026-07-30に「暖色系が見にくい」という指摘を受け、再度寒色系へ変更した
（今回はスティールブルー単色ではなく、`dataviz`スキルの検証済み参照パレット1・2番目のスロット
＝ブルー×オレンジのペアを採用）。他社資料と束ねて使う前提のため、装飾（縁取りストライプ等）は
引き続き入れない。

| 用途 | HEX | 備考 |
|---|---|---|
| 地色 | `F7F9FB` | スライド背景。寒色寄りのほぼ白 |
| インク（本文） | `1F2937` | 紺寄りのほぼ黒（スレート） |
| インク（ミュート） | `52616B` | ラベル・キャプション |
| インク（フェイント） | `8A97A0` | 軸ラベルなど最も控えめなテキスト |
| 罫線 | `D9E2EA` | カード・チャート枠線 |
| 罫線（薄い） | `EDF1F5` | グリッド線・コメント欄の罫線 |
| アクセント | `2A78D6` | 見出しの強調色。ブルー（dataviz参照パレット スロット1） |
| アクセント（淡） | `E4EEFC` | KPIカードの背景塗り |
| 系列色1（売上・限界利益率など「主指標」） | `2A78D6` | ブルー |
| 系列色2（受注・労働分配率など「対になる指標」） | `EB6834` | オレンジ（dataviz参照パレット スロット2。スロット1と組み合わせて使うことが前提の検証済みペア） |
| 良い変化 | `006300` | 濃緑（dataviz参照パレットの「delta good/success text」相当） |
| 悪い変化 | `D03B3B` | 赤（dataviz参照パレットの「critical」相当） |

系列色（`2A78D6` / `EB6834`）は地色`F7F9FB`に対し
`dataviz` スキルの `scripts/validate_palette.js` で2026-07-30にlightモードpass確認済み
（`node scripts/validate_palette.js "#2a78d6,#eb6834" --mode light --surface "#F7F9FB"`。
CVD分離ΔE 24.7・通常視ΔE 33.6でいずれも閾値を大きく上回り、直接ラベル併用の必須要件は無いが、
このデッキは各チャート上部にキャプションで系列名を明記しているので念のため満たしている）。
このスライドはPowerPoint出力のみで表示モードの切替がなく背景色`F7F9FB`固定のため、
dark modeの検証は対象外（artifactのような画面のライト/ダーク切替がある場合のみ両方確認する）。
系列色を再度変える場合は同じ手順で必ず再検証すること。

## フォント

- 見出し・本文・数値とも：Noto Sans JP

ユーザーのグローバル設定（`~/.claude/CLAUDE.md`）で、Word/Excel/PowerPoint資料共通の既定書体として
指定されている。本人PCには`NotoSansJP-VF.ttf`としてインストール済みで実機PowerPointで正しく表示される。
ただし社内の他部署・他社と共有する場合、相手PCに未インストールだと代替書体で表示される可能性がある点は
資料作成のたびに一度ユーザーに触れておくとよい。
QA用にPowerPoint COM経由で書き出した画像で見た目を必ず確認すること（文字量とボックス幅のバランスは
実際のレンダリングで確認する）。

## レイアウト構成（縦方向、上から順）

1. **ヘッダー**：会社名（左、太字19pt）＋ 対象月／作成日（右寄せ）。
   下線を1本引くのみ。**レポートタイトルや「◯◯レポート」的な文言、フッターのブランド表記は
   入れない**（他社資料と束ねて使うため、装飾的な見出しは不要という利用者の要望に基づく）。
2. **KPIカード（横並び。枚数は`data.json`の`kpis`配列の要素数に自動追従）**：
   通常は受注高・売上高・限界利益率・労働分配率の4枚だが、受注データが無い会社では
   売上高・限界利益率・労働分配率の3枚になる（`build_deck.js`はカード幅を要素数から
   自動計算するので、コード側の変更は不要）。各カードは`references/calc-rules.md`の
   指標をすべて1枚に収める4行構成：
   - ラベル
   - 当月実績（大きい数字＋単位）
   - 目標比／前月比（横並び、太字・色分け）
   - 3ヶ月平均実績＋3ヶ月平均の前期間比（小さめ・ミュート色）
   背景はアクセント淡色の角丸カード。**カードの縁に色付きストライプを入れない**
   （AI生成デザインっぽく見えるための回避）。
3. **チャート（横並び。枚数は`data.json`の`charts`配列の要素数に自動追従）**：
   典型例（受注データがある会社の場合）：
   - 売上高・受注高の推移（線グラフ、千円）
   - 限界利益率・労働分配率の推移（線グラフ、％）
   - 受注残の代理指標（受注高－売上高の累積差、面グラフ）
   受注データが無い会社では「売上高の推移」「限界利益率・労働分配率の推移」の2枚になる。
   すべてPowerPointのネイティブグラフ（`addChart`）で作る。画像に焼かない
   （数値を後から確認・編集できるようにするため）。
4. **下段（`extraSection`の有無・`layout`で構成が変わる）**：
   - `extraSection`が無い場合は2カラム：
     - 左：「所見」見出し＋箇条書き＋最後に「データ注記」
     - 右：「コメント」見出し＋罫線入りの空白ボックス
   - `extraSection.layout === "column"`（既定）の場合は3カラム：
     - 左：「所見」（やや狭く、フォントも小さめ）
     - 中央：`extraSection`のタイトル・サブタイトル・中身（表 or 箇条書き）・注記
     - 右：「コメント」（やや狭くなるが空白ボックスは維持）
   - `extraSection.layout === "page"`の場合：1枚目は所見／コメントの2カラムのまま、
     `extraSection`は2枚目に全面レイアウトで独立させる（タイトル・サブタイトル・
     大きめフォントの表 or 箇条書き・注記）
   「コメント」欄は常に**罫線入りの空白ボックス**（あとで手書き・追記するためのスペース。
   AIが下書きコメントを埋めない。これは利用者から明示的に要望された仕様で、会社が変わっても
   踏襲する）。

見出し文字に**下線・左ボーダー等のアクセントラインを付けない**（同上の理由）。

### extraSectionの仕様

会社特有の指標（受注TOP10、設備稼働率など）を表現する汎用枠。`scripts/build_deck.js`の
JSDocコメントと`SKILL.md`「5. 会社特有の指標（extraSection）」に詳しいスキーマがある。
要点：
- `kind: "table"`：`columns`（`key`/`label`/`align`/`width`。`width`省略列は残り幅を均等割り）
  と`rows`（`columns`の`key`をプロパティ名とするオブジェクトの配列。表示用に整形済みの
  文字列を渡す——カンマ区切りや`%`付与はdata.json側で済ませておく）
- `kind: "bullets"`：`bullets`（文字列配列）を箇条書きとして描画
- `layout: "column"`のときは表の行数の目安は10行前後まで（列数・列幅にもよる。QA画像で
  行が窮屈でないか必ず確認する）。それを超える、または情報量が多いときは`"page"`にする

## 数値フォーマット

- 金額：`#,##0` 千円単位（元データが円建てなら1,000で割る）
- 比率：小数点1桁 + `%`
- ポイント差：小数点1桁 + `pt`（符号は▼▲などの記号、または `+`/`▼` で明示。
  「％」と「pt」を絶対に混同しない）
